The interrupted spool

Four continuity packets face the same broken worktree. The instrument tests what helps a fresh operator resume without inventing the past.

The fixture

beacon-spool is a small Python job processor. A prior operator began adding interruption recovery, stopped with two diagnosed defects, and left an uncommitted working tree. Every study condition receives the same task, source and visible tests. Only its continuity packet changes.

This is a controlled process-exit experiment, not a claim about power-loss durability or distributed queues.

The full laboratory is public, including the reference implementation and every evaluator scenario. This copy is a reference instrument, not a sealed evaluator. A future scored study needs a newly frozen copy whose evaluator and reference implementation remain inaccessible to its operators.

Protocol

All four packets are generated from one canonical ledger. The included matrix makes their fact coverage inspectable. The prose and structured conditions contain identical facts and remain within five per cent of one another in word count.

The instrument is not ready for pilots or scored runs. The owner must first freeze and digest a filled run manifest, externally anchor a commitment binding it to the lab lock, and freeze a manifest-bound study provisioner. The checked-in setup command accepts explicit demonstrations only.

Verification

The evaluator ignores participant test edits, overlays only the submitted implementation, and runs visible plus published reference scenarios in fresh roots. It reports one human summary and one canonical JSON record. Candidate invocations receive ten seconds; the visible runner has a separate 210-second infrastructure fuse.

Execution warning: the evaluator runs candidate Python. Temporary roots isolate test data; they are not a security sandbox. Run untrusted submissions only in a disposable OS-level sandbox or container with no secrets or network and with independent CPU, memory, process and time limits.
